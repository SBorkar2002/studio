# Truth: claims, credit and confidentiality

Use this whenever copy talks about Sejal's work: case studies, resume, portfolio text, cover notes, application answers, LinkedIn.

## The three questions for every claim

1. **Did she do it?** If someone else did it (a teammate's post, a client's script art), say so or cut it.
2. **Where is the source?** A file, a link, a commit, a number she gave. No source means TODO, never filler.
3. **Can she defend it in an interview?** If a hiring manager asks "how?", is there a real answer?

## Rules

- No invented metrics. Ranges or "25+" style numbers only when she chose that framing.
- Credit Claude only for what Claude did (research synthesis, QA, code with her direction). Never write that Claude "designed" her work, and never undersell her design decisions either.
- She works in Next.js and React **with Claude Code**. Do not claim she is a senior engineer.
- One user's feedback is not "users said". Count honestly.
- Client and employer work: public material only. Anonymise names and stock photos in take-homes before they go public. Wait until a hiring process is closed before publishing its take-home, unless she decides otherwise.
- Check `private.local.md` for confidential items before writing anything public.

## Tone (resume, notes, answers)

- Should not read as AI-written: vary sentence length, no "so that" tails, no "end to end", no "seamless", "leverage", "elevate", "delve", "robust". <!-- lint-ignore -->
- ATS friendly for resumes: plain section names, no tables for core text, keywords from the job description used honestly.
- Short. Every line earns its place.
